## 使用约定

1. **一次一批**：按序号执行；完成一批后勾选该批 checkbox，并把状态回填下表。
2. 结论已冻结（见 `00-overview.md`「冻结结论」）。实施中若发现结论本身有问题，先改结论再改代码。
3. 本目录只写计划，不改产品代码；不改 `AGENTS.md`。
4. 每批结束必须有「功能不缺失」证据：`pytest` + 渲染像素 sha256 比对 + QML 装载冒烟（见 `07`）。
5. 批次内禁止夹带行为改动；发现顺路可改的行为问题，只记录到该批「顺带发现」小节，不实施。
6. **批次 0 先行**：审计指标、像素 sha256、测试数、QML 装载基线全部填进 `07` 的表格后才动第一批；基线未落地就开批 = 违规。

## 建议的会话切分（7 次，含 1 次返工缓冲）

一次会话 = 一个批次（或"低风险批次 + 相邻批次"），会话内可以多个 commit，但**不跨批混改**。理由：每批结束都要过 4 项验收（`07` §7.1–7.4），而验证由用户本机运行（铁律 3），所以会话边界天然对齐"交接—验证"；两批挤在一次会让失败归因与回滚粒度都变模糊。

| 会话 | 批次 | 为什么这样切 | 预期改动面 |
|---|---|---|---|
| 1 | **0 + 1** | 基线是测量（低成本、必须最先）；批次 1 是纯机械搬迁，与基线同次不失控，且它是后续一切的前置 | 22 个模块搬家 + ~40 行导入替换 + spec 一行 |
| 2 | **2** | 含**高危点**（`conftest.py` 的字符串 patch 目标）：需要"改完核对真实偏好文件未被写入"这种细验证，独占一次 | 3 文件 → 12 文件（偏好 5 / 线程 5 / 网络 2）；调用点 24 处 + conftest |
| 3 | **3** | 改 `core` 内部结构 + 文本域跨包迁入；像素判据最强，适合独立验证 | 1 拆 7 + 5 处搬迁；`core`/`gui`/`tests` 调用点 ~14 |
| 4 | **4.1** | 唯一"静态检查看不到"的风险（QML 按名调用），安全网最弱 → 独占一次，一小步一 commit | 1 → ~7 文件，声明与实现分离 |
| 5 | **4.2 + 4.3**（可跳过 4.2） | QML 组织类改动同类，合一次；若跳过子目录重组则本次只拆大对话框，或并入会话 6 | QML ~28 文件移动（若做）+ 1 拆 3 |
| 6 | **5** | 量大但低风险（命名 + 注释），失败代价低、可与前一批准验证串起来 | 范围内 ~35 文件的 docstring + 命名项 |
| 7 | **6 + 7** | 性能项按证据逐项做（多数可能回退，收敛快）；收尾的对照表与 `AGENTS.md` 同步一次性完成 | 视项而定 + 文档 |
| 缓冲 | — | 任何一批验收失败 → 增加"修一次"会话，不把修复塞进下一批 | — |

**可变点**：跳过批次 4.2 → **6 次**；跳过批次 6（性能全部不做）→ **6 次**；两者都跳过 → **5 次**。不建议更少：批次 2/3/4 的失败原因类型不同，合并后无法归因。
