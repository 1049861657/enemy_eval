# 总览（2026-10-06）：AI 评价（杰斯顿）

本计划引入 AI 评价：把当前卡片的敌人数据与一份冻结的杰斯顿基准数据交给模型，由杰斯顿的口吻点评这名敌人。**任务书已定稿；任务 01–05 已实施、待本机验证（任务 03 的人设与提示词待审改，任务 05 另含打包实测）。** 实施按 `01 → 02 → 03 → 04 → 05` 顺序执行。

## 需求

用户原话：引入 AI；让杰斯顿与当前卡片的敌人进行数据比对，给出他的评价；首先是保留一份杰斯顿的数据。

| # | 目标 | 可观测结果 |
|---|---|---|
| G1 | 库内冻结杰斯顿·威廉姆斯的级别0 数据作为基准 | 基准 JSON 可直接阅读核对；打包后仍可读 |
| G2 | 手动触发，产出杰斯顿口吻的敌人点评 | 点击顶栏按钮打开「AI 评价」面板（可改提示词、预览实际请求），点「生成」后给出简评，可采纳或关闭；点评对象是这名敌人本身，不逐项复述数值 |
| G3 | 结果不自动落盘，采纳后可一步撤销 | 采纳即写入当前卡简评；`Ctrl+Z` 一步回退 |

## 边界结论（已定，实施时不得偏移）

| 项 | 结论 |
|---|---|
| 杰斯顿定位 | 两者兼有：既作数值基准数据，又作毒舌评委人设 |
| 基准锚点 | 单一基准：杰斯顿的数据只作说话人的参照系，**不要求逐项对照**；不做跨类降级标注，不建分档标尺 |
| 基准结构 | 一份**手写 JSON**，键名与卡面字段同名，只含外发字段；**不接 `EnemyData`**、编辑器不可读；多阶段信息走 `talents_abilities` 文本字段 |
| 比对方式 | 两份数据整包交给模型；产物是**对这名敌人的点评**，不是差异清单；**不预计算差异表、不做档位判定**；提示词只解释易搞反字段的方向与量纲，并明令禁止逐字段复述 |
| 产出范围 | **仅简评**（写入 `brief_comment`），≤100 字：先说整体印象，再说战斗用途与难缠之处；评分与等级仍全人工 |
| 产出格式 | 纯简评正文：不带「简评：」前缀（渲染层已加，`core/render/sections/rating_grade.py:351`）、不带引号、不带自称署名 |
| 称呼 | 不出现人称：不写「它 / 他」之类指代，直接用「血量」「防御」这类主语 |
| 自称 | 允许第一人称；自身数据最多自比一次，不作逐项对照 |
| 评价宽度 | 可评机制与能力表现（技能、天赋文本），也评威胁、长处与短板；**不评设计好坏与新旧** |
| 人设尺度 | 温和毒舌，评的是战斗表现；不拉踩设计者、其他敌人、作者；产出可直接对外展示 |
| 触发入口 | 顶栏独立按钮，与「参考 PRTS」并列（`gui/qml/CommandBar.qml:197`）；点击先打开「AI 评价」面板 |
| 触发时机 | **仅手动**：只有面板内点「生成 / 重新生成」才发起请求；打开面板、改提示词、展开预览、打开配置、切卡、改字段、刷新预览、启动应用均不触发、不预热、不预取 |
| 等待反馈 | 面板内点「生成」后生成按钮立即忙态，状态栏同步写「正在生成 AI 评价（模型）…」，结果到达后直接显示在面板的简评区；请求在后台线程，等待期间界面不阻塞 |
| 触发门槛 | 不设：新建卡的占位数据也允许触发 |
| 未配置时 | 点「生成」时未配置 → 打开设置框（面板保持打开），不发请求 |
| 提示词 | 面板内可编辑，随偏好 `ai_prompt` 落盘（空＝沿用内置默认 `utils/ai_prompt.py::DEFAULT_PROMPT`，默认文案升级自动生效）；点「生成」时保存并生效；面板可展开「实际请求」查看与真实请求同源的拼装结果 |
| 面板内容 | 人设头（「杰」字瓦片 + 「杰斯顿的点评」 + 对象名 · 模型名 + 状态徽标：已配置 / 生成中 / 未配置）+ 提示词条（**默认折叠**，折叠时标出「内置默认 · N 字」或「自定义 · N 字」）+ 可展开的「实际请求」条（折叠时已显示 `POST <端点>`）+ 简评卡片（左引言条 + 引号水印 + 只读可选中复制、超长滚动 + 底部「N 字」与目标 ≤100 刻度）+ 未配置时的内联横幅（含「去设置」）；空态为引号 + 「点「生成」，让杰斯顿点评这张卡」，生成中为骨架条；**不展示**数值对照、技能 / 天赋 / 简介文本 |
| 面板能力 | 生成 / 重新生成（同参数再请求一次）、采纳、关闭；`Ctrl+Enter` 生成、`Esc` 关闭；生成中禁用生成与采纳，关闭即作废并取消在飞请求 |
| 采纳形态 | 覆盖当前卡简评；采纳前比对请求时快照与当前卡数据，不一致先提示再写；后续润色复用既有简评编辑器，不新增编辑控件 |
| 结果缓存 | 不缓存、不跨卡片复用：每次请求只服务当次点击 |
| 请求中途切卡 | 结果作废并记日志，沿用渲染侧 `revision` 丢弃过时结果的既有做法（`gui/render_coordinator.py:131`）；作废时给一条 toast 说明本次已作废（渲染侧静默丢弃属被动重绘，AI 是用户主动点击，不沿用静默） |
| 留痕 | 简评不带上卡面的来源标注；应用日志记一笔（耗时、成败、模型名） |
| 超时与重试 | 固定读超时 120 秒（`connect` 5 / `write` 10 / `pool` 5 不变；不暴露设置项）；**一律不自动重试**：解析失败、网络与状态码失败都直接报错，要再来一次由用户重新触发（含面板「重新生成」） |
| 错误分类 | 四类可区分（载体：`utils/error_handler.py` 的 `AiCredentialError` / `AiRateLimitError` / `AiServiceError` / `AiNetworkError`，异常对象经线程信号传回 GUI）：① 未配置或密钥无效（HTTP 401）→ 引导打开设置；② 限流（429）→ 提示稍后重试并带上 `Retry-After` 秒数（无该头则只说稍后重试）；③ 服务端问题（5xx）与响应无法解析 → 提示服务端异常并给出状态码（404 额外指出 Base URL 版本段）；④ 连接失败 → 提示网络不可达；读超时（120 秒）→ 提示模型响应超时；此外 402 余额/配额不足、400/422 请求被拒、503 服务繁忙各有专属文案（DeepSeek 错误码表） |
| 超长输出 | 模型不守 ≤100 字时**不裁剪**：面板内可见全文，采纳与否由人工定夺 |
| 供应商 | OpenAI 兼容 `/chat/completions`；认证 `Authorization: Bearer`；默认 Base URL 与模型名留空由用户填 |
| Base URL | 接受三种写法（根地址 / 根地址+版本段 / 完整 chat 地址），规范化到「到版本段为止」后落盘；界面实时显示最终请求地址；不做供应商预设、不做连通性检测 |
| 密钥 | 偏好 JSON 明文存，界面明文展示（不做密码框，框内如实标注）；不进日志、不进异常消息 |
| 基准时效 | 不管理：冻结即固定，不随游戏版本更新，也不留档来源与冻结日期 |
| 不做 | 多轮对话、会话历史、流式输出、自动落盘、差异表与档位判定、把当前卡旧简评喂给模型、结构化多阶段 schema、向量库 / embedding、本地推理引擎、CLI 入口改造、替用户决定 `grade`、提示词模板管理（多套保存 / 切换）、为「检查」新增测试用例（`AGENTS.md` 铁律 1） |

## 数据契约：杰斯顿基准

| 项 | 结论 | 依据 |
|---|---|---|
| 存放位置 | 打包会带上的资源目录 `resource/baseline/`，**不放 `data/`** | `enemyEval.spec:188-189` 的 `project_data = [("resource", "resource")]` 只打包 `resource/`，且按目录递归复制，子目录无需新增打包项；`data/` 是用户配置与 PRTS 调试导出，不进包 |
| 形状 | 手写 JSON，**22 个键**：13 数值 + 5 枚举 + `name` / `brief_description` / `talents_abilities` / `skills`，键名与卡面字段一致；不含 `grade` / `brief_comment` / `ratings` / `avatar_path` | 基准本身就是外发给模型的片段，无需再过滤 |
| 生成方式 | 按 PRTS `==级别0==` 块手写（本地缓存 `data/prts_debug/杰斯顿·威廉姆斯/page.wikitext`）→ 冻结入库 | 只取级别0；不走链路重建、不接 `EnemyData` |
| 多阶段 | 走既有 `talents_abilities`：放**级别0 天赋原文**，**不自拟压缩句**、不做绝对值换算、不存两套数值 | 该字段本就由 PRTS 导入填充：`utils/prts_field_mapping.py:54` 映射 wiki「天赋」→ `utils/prts_enemy_builder.py:52` 写入 → 渲染侧 `core/render/sections/skills_talents.py:45` 消费 |
| 运行期读写 | 只读：加载器返回副本、不写回；编辑流程不涉及它 | 基准是比对锚点 |

**一律剔除**：

- `avatar_path`：可能是本机绝对路径（`data/小杂毛_config.json` 里是 `E:/pythonProject/enemy_eval/enemy/墟/头像_敌人_资深的小弟.png`），含盘符与目录结构。

- `ratings` 与 `grade`：产出仅简评，两者非必需，且会把作者已给的评分与等级锚定到产出上。

## 风险总览

| 风险 | 影响 | 处置 |
|---|---|---|
| 模型把字段方向或倍数写反 | 卡片出现错误结论，产出内看不出错 | 提示词解释易搞反字段（`attack_interval` 越大越慢、`move_speed` 越大越快、`magic_resistance` 为百分比减伤）；产物以定性评价为主，卡面数值即可核对；**不采纳即无影响** |
| 明文密钥落盘 | 随配置分享外泄 | 偏好 JSON 明文存（已接受，不做加密）；界面明文展示并在框内标注；不进日志、不进异常消息、不出现在错误文案 |
| 模型不守长度上限 | 简评区撑高、卡片比例失衡 | 不做代码裁剪（避免静默改内容）；面板内全文可见，采纳前人工取舍 |
| 状态码分类缺失 | 错误提示含糊、用户不知下一步 | 四类映射见「边界结论」；任务 `03` 建异常子类并归一，任务 `05` 按子类出文案并补超时与状态码细分（402 / 400 / 422 / 503）；异常对象经线程信号（形参 `object`）传到 GUI，**不在线程内拼文案** |
| 基准文件未进包 | 发布版功能整体失效 | 基准放打包目录；任务 `02` 含打包后实测 |
| 基准混入级别1 数据 | 评价系统性偏差 | 基准只从 `==级别0==` 块取值；锚点数值（25000 / 700）写进任务 `02` 验收 |
| 基准随版本过时 | 评价偏离当前游戏数值 | 已接受：不续期、不留档，过时与否由人工判断 |
| 占位数据也能触发 | 产出无意义评价 | 已接受：不设门槛，点「放弃」收场 |
| 评价与卡面既有文风脱节 | 作者需大改才敢用 | 已接受：旧稿不外发；不满意就放弃 |
| 供应商响应格式差异 | 解析失败 | 提示词强制 JSON + 解析容错（剥围栏与首尾空白后，逐个扫描括号平衡的 JSON 对象，取第一个带非空 `comment` 的，容忍前缀说明、尾随文字与输入回显）；不自动重试，解析失败即明确报错 |
| 端点不支持某些请求字段 | 请求 400 | 请求体只用最小公共字段（`model` / `messages`），不带 `response_format` 等可选参数 |
| 线程未响应时关窗 | 残留线程 | 采用可中断形态：线程内 `asyncio.run` + 每 50ms 查 `isInterruptionRequested` 后 `task.cancel()`（`PrtsFetchThread` 范式，`utils/thread_manager.py:103-113`），关窗只 `requestInterruption` + 取消，**不 terminate**。同步请求无取消 API，故调用层同时保有一条 async 路径（任务 `03` 收尾项） |

## 验收总纲

1. 未配置密钥时打开面板并点「生成」→ 打开设置框，不崩溃、不改数据。
2. 打开敌人配置、编辑字段、刷新预览、切换卡片，直到在面板里点「生成」为止（含打开面板、改写提示词、展开「实际请求」），日志中不出现任何 AI 请求。
3. 在面板点「生成」→ 面板给出简评（提示词约束 ≤100 字，**超出不裁剪**）；简评是对这名敌人的评价，不出现逐字段数值清单。
4. 采纳 → 简评写入当前卡，`Ctrl+Z` 一步回到原值。
5. 断网时点击 → 分类错误文案，卡片数据不变。
6. 打包产物启动后点击 → 能读到基准并产出结果。
7. 面板的「实际请求」与真实发出的 body 同源（system = 当前提示词、user = 两份数据）；提示词栏默认折叠并标出当前用的是内置还是自定义；改提示词后点「生成」→ 偏好 `ai_prompt` 更新，重开面板仍显示该文本；点「恢复默认」回到内置文案。
