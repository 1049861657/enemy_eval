# 总览（2026-10-06）：PRTS 导入的多级别支持

## 需求

用户原话：导入 PRTS 没有去甄别级别 0/1/2…；每个敌人都有至少两个级别，所以不让用户在选择上花步骤——跟现在一样导入最高级别，但要在恰当的页面加入切换级别的按钮，并提示该敌人存在多个级别。

| # | 目标 | 可观测结果 |
|---|---|---|
| G1 | 导入保持一步到位 | 导入过程与改动前完全一致（取最高级别，无新增询问、无额外请求） |
| G2 | 导入后能把当前卡换到该敌人的其他级别 | 出现临时的级别切换控件；切换后数值随之变化，`Ctrl+Z` 一步可回退 |
| G3 | 作者知道这个敌人有多个级别 | 控件出现即表明有多级；展开菜单可见全部级别名 |
| G4 | 切换控件是临时的 | 换卡（打开 / 新建 / 重置）或重启后消失；不写入卡片、不写入偏好 |

## 现状（已核对）

| 事实 | 位置 |
|---|---|
| 合并逻辑取出**全部** levelcontent 块并按 `index` 升序覆盖 → 结果恒等于最高级别；**本计划把这一行为保留为导入默认** | `utils/prts_field_mapping.py::build_enemy_raw`（`level_index=None`） |
| 技能槽与异常抗性同为跨级累加 | `utils/prts_field_mapping.py::_merge_skill_slots`、`ab_acc` |
| 已能拿到全部级别块与每块的 `index`，只是从不使用「有哪些级别」这一信息 | `utils/wiki_template_parser.py::_extract_all_template_bodies` |
| 导入后没有任何切换手段，作者也无从知道页面存在多个级别 | `gui/qml/PrtsQueryDialog.qml`、`utils/thread_manager.py::PrtsFetchThread` |
| 构建时缺省字段回退卡片默认值 → 直接套用会重置简评 / 评分 / 头像 | `utils/prts_enemy_builder.py::to_enemy_data` |
| 页面级消歧**已解决**，不属本计划范围：`resolve_enemy_page_title` 用 `[[分类:敌人]][[名称::X]]`，实测 `名称::W`、`名称::霜星` 各命中 1 个 | `utils/prts_api_client.py::resolve_enemy_page_title` |

## 官方机制与 API 调研结论

### 1. 级别是「上一级的增量覆盖」

页面结构（实测 `?action=raw`，2026-10-06）：

```
{{敌人信息/common2|名称=…|地位级别=领袖|描述=…|伤害类型=物理|攻击方式=近战 远程|行动方式=地面|能力=…}}
==级别0==
{{敌人信息/levelcontent|index=0|最大生命值=25000|攻击力=700|防御力=400|…|技能0=…|天赋=…}}
==级别1==
{{敌人信息/levelcontent|index=1|最大生命值=40000|攻击力=800|天赋=…}}
```

`级别1` 只声明三个字段，其余字段没有重复写。模板源码给出机制（`模板:敌人信息/levelcontent?action=raw`）：

- 缺省参数回退到**上一级**：`{{#ask:[[{{FULLPAGENAME}}#LEVEL{{#expr:{{{index}}}-1}}]]|?字段}}`；
- 解析结果整体写入子对象：`{{#subobject:LEVEL{{{index}}}|名称=…|最大生命值=…|…}}`。

**推论：取第 k 级的正确数值 = 从 index=0 起逐级覆盖到 index=k。** 现有实现对「全部级别」做这件事，所以恒等于最高级别；切换功能只需把「覆盖到哪一级」变成参数。

### 2. SMW 子对象可直接查询，且返回解析后的完整字段（实测）

```
action=ask&query=[[-Has subobject::杰斯顿·威廉姆斯]]|?名称|?最大生命值|?攻击力|?防御力&format=json
```

| 子对象 | 最大生命值 | 攻击力 | 防御力 |
|---|---|---|---|
| `杰斯顿·威廉姆斯#LEVEL0` | 25000 | 700 | 400 |
| `杰斯顿·威廉姆斯#LEVEL1` | 40000 | 800 | 400 |

- `LEVEL1` 的 `防御力=400` 在 wikitext 中并未出现，是继承结果 → 子对象存的是**解析后的完整值**。
- `query.meta.count` 即级数；单级页只有 `#LEVEL0`。
- 单级精确查询：`[[<页面>#LEVEL<k>]]|?<属性>`。
- 属性类型不统一（`最大生命值` 为 `_num`，`攻击力`/`防御力` 为 `_txt`），取回后仍需按现有 `_to_int` / `_to_float` 规整。

### 3. 样本级数（支撑「导入免选择」的前提）

实测 7 个敌人（源石虫、猎狗、爱国者、塔露拉、萨卡兹术师、梅菲斯特、杰斯顿·威廉姆斯）**均为 2 级**（`#LEVEL0` + `#LEVEL1`，`meta.count = 2`）。因此导入时不做询问、把级别切换放到事后，是合理的交互取舍；实现仍按 N 级泛化，并把「只有 1 级」当合法输入处理。

## 边界（结论）

| 项 | 结论 |
|---|---|
| 导入默认 | 取最高级别（现状不变），不新增询问步骤 |
| 上下文保留 | 导入成功后保留**本次导入上下文**（页面标题、整页 wikitext、级别列表），只留一份、不落盘；**当前级别归卡片模型**，不在上下文里留影子 |
| 切换控件 | 仅当级数 ≥2 时显示；**位置：预览列工具行右侧**（`gui/qml/PreviewViewport.qml` 的工具栏 `RowLayout`，「导出」左侧）：`AppButton` + `AppMenu`，按钮显示当前级别名，菜单项即各级别名（`级别0` / `级别1`）；**不显示数值、不加提示文案**。与更新提示条无关——后者是强提醒，位置不动 |
| 组件契约 | 预览组件只收属性、发信号：`prtsLevelsJson` / `prtsLevelIndex` 属性与 `prtsLevelChangeRequested(int)` 信号，由 `Workspace`（`gui/qml/Workspace.qml:297`）绑定桥接属性与槽；**不把 controller 塞进预览组件**；文件首行需 `pragma ComponentBehavior: Bound` |
| 提交入口 | 切换走 `gui/card_model.py::apply_enemy_data`（整份数据一步入栈）；禁止 `set_enemy_data` |
| 控件生命周期 | **临时**：换卡（打开 / 新建 / 重置数据）、关闭控件或重启应用即消失 |
| 请求次数 | 切换用内存中的 wikitext 重新构造，**零额外请求**；上下文失效后不提供切换 |
| 覆盖范围 | 只覆盖 PRTS 来源字段：18 个战斗字段 + 5 个枚举 + `brief_description` + `talents_abilities` + `skills`；**保留** `brief_comment`、`ratings`、`grade`、`avatar_path` |
| 撤销与级别回放 | 「数据 + 级别来源」成对快照（`gui/undo_stack.py::_CardSnapshot`），`Ctrl+Z` / `Ctrl+Y` 同时回放数据与级别指示；级别编号唯一归属 `gui/card_model.py::CardModel.prts_level_index`，桥接与会话上下文不留影子 |
| 级别可见性 | 不写入卡片文件、不加字段；级别编号是卡片模型的运行期状态（随撤销栈回放），级别列表随本次导入上下文消失 |
| 数据源 | 生产只用 wikitext；SMW 子对象只作开发期校验 |
| 不做 | 改 schema、加「级别」字段、导入时选择、多级批量导入、多页面选择、重写抓取链路 |

## 风险

| 风险 | 影响 | 处置 |
|---|---|---|
| 覆盖白名单写错 | 抹掉作者的简评与评分 | 白名单显式列出；验收第 5 条覆盖 |
| 误用 `set_enemy_data` | 切换不可撤销 | 明确禁用；验收第 3 条覆盖 |
| 重复点击并发切换 | 结果错乱 | 复用 `prtsBusy` 串行化 + `revision` 丢弃过时结果 |
| 临时上下文与当前卡不一致（换卡后残留） | 控件指向错误对象 | 单槽、换卡即清空；验收第 7 条覆盖 |
| 内存驻留整页 wikitext | 占用上升 | 单槽、换卡即释放，不累积 |
| 只有 1 级的敌人 | 不显示控件即为正确行为 | 控件仅在级数 ≥2 时出现（验收第 6 条） |
| 预览工具行变拥挤 | 该行控件被挤压 | 级别控件插在「导出」左侧并保持单行；标题已带 `elide` 与最小宽 96（`gui/qml/PreviewViewport.qml:41-52`） |
| 撤销后级别指示与数据不一致 | 界面显示错误的级别来源 | 级别来源随 `_CardSnapshot` 成对快照回放；验收第 3–4 条覆盖 |
| 某级缺 `index` 或非数字 | 覆盖顺序错乱 | 既有 warning 保留，并把异常事实返回上层，UI 不静默排序 |

## 验收总纲

见 `01-prts-level-selection.md` 的验收 1–9 条（涵盖导入不回归、控件出现与临时性、切换生效与可撤销、**级别随撤销栈同步回放**、保留作者字段、单级不出控件、切换零请求、SMW 交叉核对）。

## 回滚

解析层与切换入口均为在既有链路上加一层；回滚即撤掉该层。无数据迁移。
