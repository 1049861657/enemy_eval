# Proposal

## Why

所有外发网络请求目前没有统一的代理策略：PRTS 页面与头像请求使用显式传输层，完全绕过代理；AI 评价与更新检查则隐式跟随环境变量/系统代理。用户无法按网络环境控制行为，同一台机器上不同功能会走不同链路。

## What Changes

- 新增应用级设置「代理模式」，取值仅两种：跟随系统、不使用代理；持久化到用户偏好文件，默认「不使用代理」。
- 该设置统一作用于全部外发 HTTP 请求：PRTS 页面查询与头像下载、AI 评价、更新检查；GUI、命令行与 `scripts/` 一致。
- PRTS 通道改为遵守该设置（当前恒为直连），默认值下行为不变。
- AI 评价与更新检查在默认值下改为直连（当前跟随代理），这是用户可感知的行为变化。
- 「跟随系统」沿用 AI 评价现有语义：httpx `trust_env`，环境变量优先，未命中再读操作系统设置；其行为若不合适，后续单独优化。
- 代理模式是应用级单一设置，不按模块拆分（PRTS / AI 评价 / 更新检查共用同一档位）。
- 不提供自定义代理地址与认证代理。
- 收敛重试层：内层传输不再自行重试，由请求层统一重试网络错误与 502/503/504，避免嵌套放大。
- PRTS 响应正文不是合法 JSON 时按既有错误路径返回；解析定位阶段失败退回裸名，不中断整次拉取。
- PRTS 每个请求记录 DEBUG 级状态与耗时，便于代理与网络排障。

## Capabilities

### New Capabilities

- `outbound-proxy`: 规定应用级代理模式的可选值与默认值，以及所有外发 HTTP 请求在两种模式下的统一代理行为。
- `network-resilience`: 规定外发请求的单层重试与异常响应处理，避免嵌套重试和未处理异常。

### Modified Capabilities

无。`openspec/specs/` 目前没有既有能力，现有网络行为未被任何 spec 覆盖。

## Impact

- 偏好：`app_settings.json` 增加一个字段；旧文件缺该字段时按默认值读取。
- 网络层：PRTS、AI 评价、更新检查三条请求链路的客户端构造；PRTS 重试层收敛、非 JSON 响应归类与请求日志。
- 界面：更多菜单内的聚合设置对话框（AI / 网络）与当前模式回显；关于对话框保留更新检查开关。
- 脚本：`scripts/` 下的联网冒烟脚本继承同一策略。
- 无新增第三方依赖。
